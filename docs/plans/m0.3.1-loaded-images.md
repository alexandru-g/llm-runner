# Plan: run containers from images delivered as files (`docker save`/`docker load`)

Requested by SS6M A0 on 2026-10-23 for air-gapped hosts in general. Status:
**approved by Alex on 2026-10-23, implemented for v1.1.0.** It blocks A0's DoD 2b (install on ws after
removing the image). Everything here is general llmctl behaviour.

## The problem

llmctl pins images by the multi-arch **index digest**
(`vllm/vllm-openai@sha256:c2914767…`). The compile-cache rule `digest` and
`llmctl images` use the same identity. A host that gets the image as a file
loses that name:

- `docker save repo@sha256:<index>` writes `RepoTags: null`. With the classic
  store (overlay2, as on ws) the archive holds a **rewritten** platform
  manifest: uncompressed layers and a new digest. Checked on ws with
  python:3.12-slim: the registry's amd64 manifest is `e8a388…`, the saved one
  is `9ff2bb…`. The index itself isn't in the archive.
- After `docker load`, the image has no tag and no RepoDigest.
  `repo@sha256:<index>` doesn't resolve, and `docker run --pull never` fails.
  A digest can't be attached by hand (`docker tag` refuses digests).

What does survive is the **config digest**, which is the classic store's
image ID: `sha256:a33c10…` for python:3.12-slim, `sha256:fba1a502…` for vLLM
v0.29.0 amd64. It's a hash of the image config, and the config lists the
`diff_id` of every layer, so it pins the full filesystem. `docker load` checks
the layers against it. `docker load` prints it ("Loaded image ID: sha256:…").

The registry links the two: hash(index) = the index digest → the index lists
the platform manifest by digest → hash(manifest) = that digest → the manifest
names the config digest. Checked on ws for python:3.12-slim: index `cb33f7…`
→ amd64 `e8a388…` → config `a33c10…`, the local image ID.

## Design: run by the verified image ID, keep the index digest as the identity

1. **`images.json` gets the chain for the images llmctl ships.** A new
   key per image (additive, so schema `llmctl-images/1` stays):

   ```json
   "by_platform": {
     "linux/amd64": {"manifest": "sha256:…", "config": "sha256:fba1a502…"},
     "linux/arm64": {"manifest": "sha256:…", "config": "sha256:…"}
   }
   ```

   `scripts/pin-images.py` fills it from the registry at release time and
   checks that every hash in the chain matches. The values come with the
   llmctl package itself, so an offline host trusts nothing new.

2. **Resolving a pinned ref at `run` / `apply` / `restore`.** If
   `repo@sha256:<index>` is present locally, nothing changes. If it isn't:
   - find the expected IDs for this host's platform: from `images.json`, or
     from a chain recorded by `llmctl images load` (step 4);
   - `docker image inspect <id>`. If it's there, run `docker run … <id>`.
     The ID is immutable, and `--pull never` still applies.
   - On a classic store the loaded ID is the config digest, so `images.json`
     alone is enough: a plain `docker load` followed by `llmctl run` works.
   - On a containerd store (orin) the loaded ID is the digest of the
     manifest *in the archive*. A `docker save` from a classic host rewrites
     that manifest, so its digest isn't in the registry chain. Those hosts
     need `llmctl images load` (step 4), which records the ID after checking
     the archive.
   - **No tag fallback.** A ref with no chain stays "not on this host" and
     gets a better hint (`llmctl images load FILE`).

   The runtime record keeps `image` = the index-digest ref and `digest` = the
   index digest. So the cache rule `digest`, exported caches, `apply`
   comparisons and `ps` don't change. A new `image_id` field records what
   actually ran. It's additive in `/v1/models` and the model log ("image: … →
   loaded as sha256:fba1…").

   With 1 and 2 alone, **A0's existing bundle works without a new step**:
   ss6m-model runs `docker load` on the tar, checks the ID, and the fragments
   with `image: vllm/vllm-openai@sha256:c2914767…` run.

3. **`llmctl images save REF|BACKEND -o FILE [--platform P] [--json]`.** It
   runs `docker save` and adds one file, `llmctl-image.json`, to the archive.
   That file holds the ref, the platform, and the **raw bytes** of the index and
   the platform manifest. `docker load` ignores the extra file (checked on ws).
   The bytes come from the registry through `skopeo inspect --raw`. skopeo is
   required (Alex, 2026-10-23); `save` exits 6 without it, in offline mode,
   or when the registry is unreachable. This makes archives
   of images that aren't in `images.json` self-verifying.

4. **`llmctl images load FILE [--json]`.**
   - Checks the chain before loading. It reads `llmctl-image.json`, or for a
     plain `docker save` tar, matches the archive's config digest against
     `images.json`.
   - Reads the archive's own `manifest.json` `Config` and its `index.json`
     manifest digest before loading. The config must be the one the chain
     names. The archive's manifest digest is accepted as the ID on a
     containerd store. ss6m-model checks the same two digests (agreed with A0;
     on the vLLM tar: config `fba1a502…`, manifest `5afd5438…`).
   - Runs `docker load` and confirms the loaded ID is one of those two.
   - Records the chain and the loaded ID in `<state>/images.json`, so step 2
     resolves it on either store and for images that aren't shipped.
   - Tags the image `llmctl/<repo>:<index digest, 12 chars>` so that
     `docker image prune` can't delete it. An image with no tag counts as
     dangling. The tag is never used to find or run the image.

   Exit codes (same meaning as today): 3 = the archive isn't a docker
   save, or no chain names its image; 4 = a digest in the chain doesn't match;
   6 = docker unavailable / the registry is unreachable (save only).
   `llmctl images` shows images loaded by ID as present.

5. **`llmctl images` warns about pinned images that prune would delete.** Images
   pulled by digest have no tag either; on ws, the vLLM and llama.cpp
   images are in `docker images -f dangling=true`. `llmctl images --protect`
   adds the same `llmctl/…` tag.

6. **Option (b), a full OCI index copy:** deferred. On a containerd store it
   would keep the index digest, so plain `docker load` would work there too.
   It would mean shipping every platform's layers (vLLM about 2×) or a
   partial index that `docker load` may reject, and it doesn't help classic
   hosts. `llmctl images load` covers containerd hosts until then.

## Tests

- **Unit tests** (fake docker): chain verification (each tampered hash → 4);
  resolution order (ref present → ref; missing ref → ID; neither → error,
  no tag fallback); save embeds and load reads `llmctl-image.json`;
  plain-tar load is matched through `images.json`; the runtime record keeps
  the index digest.
- **Live on ws**, scheduled with A0. A0 and A2 also use the vLLM image, so
  the test removes only its digest reference, not the image:
  1. Keep the image with a temporary tag (`docker tag sha256:fba1a502…
     llmctl-test/vllm:keep`), then `docker rmi vllm/vllm-openai@sha256:c2914767…`.
     The layers stay, and the ref no longer resolves.
  2. `docker load` A0's tar
     (`/fast/ss6m-bundles/ss6m-bundle-llm-assistant-0.1.0/images/vllm_vllm-openai.tar`,
     21.7 GB) and check that it reports ID `sha256:fba1a502…`.
  3. `llmctl run --runtime docker` with the index ref, which should run by ID.
  4. Install the bundle with its exported cache and check the log shows
     `cache rule: digest` and the AOT load.
  5. Repeat steps 1–3 with `llmctl images save`/`load` on the llama.cpp image.
  6. Check that a tampered `llmctl-image.json` is refused.
  7. Restore the ref: `docker pull vllm/vllm-openai@sha256:c2914767…`. The
     layers are already there, so this fetches only the manifests. Reloading
     the tar wouldn't bring the RepoDigest back. Then remove the temporary
     tag.

- **Then on ws with the containerd store.** Alex will switch ws after the
  classic test. lab stays classic (60+ compose stacks).
  - Before switching: clean up the classic store (72 GB build cache, ~95 GB
    unused images). The new store doesn't follow `data-root`, so it needs
    its own location on `/fast` (`embedded-containerd`, or `root` in
    `/etc/containerd/config.toml`).
  - Alex makes the change and restarts Docker. A0 and A2 get a warning
    first.
  - Then: pull the pinned images by digest, `llmctl images load` A0's tar,
    and repeat the run, the cache hit and the tamper checks.
